01谁负责什么

模型结构在 TypeScript，设备操作在原生扩展。

协调进程管理请求、页号和引用。Prefill 与 Decode 各自拥有完整模型和 KV 池，独立执行计划；一张卡计算新 prompt 时，另一张卡可以继续输出。

协调进程不创建 CUDA context。每张卡都有一份完整模型；这里实现的是 PD 分离。

  1. 01 / RESERVE先预留两端页

    P 预留 prompt 容量，D 预留请求最大容量。目的端装不下时，请求继续排队。

  2. 02 / PREFILLP 计算并返回首 token

    完成消息代表 GPU 计算已结束。若首 token 就结束请求，可直接跳过 KV 交接。

  3. 03 / TRANSFER按页映射复制 KV

    源页与目标页可以不同、非连续。D 的 CUDA event 确认复制完成后，才返回 ACK。

  4. 04 / DECODE释放 P 引用，继续生成

    D 使用首 token 作为下一次输入。取消时，在途页仍保留到操作完成或 Worker 退出。

03已经长出了什么

区分后端，按实际验证的边界描述能力。

部分已实现当前边界
模型与文本TinyTransformer / Qwen2；safetensors 分片加载；独立 tokenizer 与模板插件greedy + EOS；尚无量化、MoE、MLA 或任意模型自动适配
Engine 调度连续调度、分块 prefill、分页 KV、完整前缀页共享、抢占重算前缀共享与抢占属于原 Engine 路径；每轮请求仍依次计算
GPU 执行完整设备前向、设备 KV、BF16 / F16 直接读取、可选 CUDA Graph激活与 KV 为 FP32；尚无 Tensor Core GEMM、FlashAttention 或张量 batch
PD 分离三进程、双卡独立推进、CUDA IPC / P2P、在途引用保护、整组失败重启尚无 PD 前缀缓存、抢占重算、D 端复制与计算重叠、跨机 RDMA
服务接口/generate JSON / SSE、健康检查、主动取消、背压与慢消费者限制SproutLM 原生协议；尚未实现 OpenAI / Codex 适配或工具调用

验证记录：39 项轻量测试、3 项双 GPU 集成测试；真实 0.5B 与 32B 短样本的完整 logits 对照、GPU 回归与 Worker 故障恢复实验。查看验证范围 ↗
